Дадлагын хүрээнд баримтад тулгуурлан асуултад хариулж, ашигласан эх
сурвалжаа харуулдаг RAG чатботын MVP хувилбарыг хөгжүүлэв. Систем нь
Fastify API, PostgreSQL + pgvector сан, вэб болон мобайл клиентээс
бүрдэнэ. Хэрэглэгч бүртгүүлэх, нэвтрэх, баримт оруулах, асуулт асуух
урсгалыг локал орчин болон бодит утсан дээр туршсан. Интерфэйсийг монгол
хэлээр хийж, кирилл монгол баримттай ажиллах хайлтын тохиргоог туршилтын
дүнгээр өөрчилсөн.

\section*{Төлөвлөгөөний биелэлт}

Удирдагчаар батлуулсан төлөвлөгөөний (Хүснэгт~\ref{tab:internship-plan})
дагуу орчны бэлтгэл, баримт боловсруулалт, хайлт, хариулт үүсгэлт, чат
интерфэйс, нэвтрэлт, өгөгдөл хадгалалт болон Docker орчныг хэрэгжүүлсэн.
Туршилтын хувьд үндсэн урсгал, зарим алдааны нөхцөлийг шалгасан боловч
500 мянган тэмдэгттэй текстийн боловсруулалтыг дуустал шалгаж амжаагүй.
Хэрэгжүүлэх явцад анхны сонголтоос дараах өөрчлөлтүүд гарсан:

\begin{itemize}
\item Арын боловсруулалтад анх төлөвлөсөн BullMQ дарааллын системийн оронд
Node.js-ийн \texttt{setImmediate} ашигласан. Нэг сервер дээр ажиллах
MVP-д Redis нэмэхгүйгээр боловсруулалтыг эхлүүлэхээр шийдсэн (4.1 хэсэг);
\item хариултыг хэсэгчлэн дамжуулах SSE (streaming)-г хойшлуулсан.
Одоогийн хувилбар хариултыг үүсэж дууссаны дараа бүхэлд нь буцаадаг.
Харин баримтын боловсруулалтын төлөвийг polling-оор шалгадаг;
\item хайлтын \texttt{threshold}-ыг анх сонгосон 0.7-оос 0.1 болгож
бууруулсан. Энэ нь хэл дамнасан хайлтын түр тохиргоо бөгөөд цаашид
асуултын орчуулгыг туршихаар төлөвлөсөн (6.2 хэсэг).
\end{itemize}

Анхны төлөвлөгөөнд байгаагүй мобайл клиентийг нэмэлтээр хөгжүүлсэн.
Уг клиентээс баримт оруулах, чатлах, эх сурвалж болон түүхээ харах,
хайлтын тохиргоог өөрчлөх боломжтой. Байршуулалтын ажил одоогоор Docker
Compose бүхий локал орчноор хязгаарлагдсан; нийтийн серверт байршуулах,
HTTPS болон автомат шинэчлэлт тохируулах ажил үлдсэн.

\section*{Байгууллагад өгөх санал}

Байгууллагын дотоод журам, гарын авлага, тайлангаас мэдээлэл хайх туслах
болгон энэ системийг туршиж болох юм. Ажилтан асуултаа бичээд хариултын
хамт холбогдох баримтын хэсгийг харах тул мэдээллийг эхтэй нь тулган
шалгах боломжтой. Мөн үйлчилгээний нийтлэг асуултад хариулахад ашиглаж
болох ч эхлээд тухайн баримтууд дээр хариултын чанарыг үнэлэх шаардлагатай.

Тогтмол ашиглалтад оруулахын өмнө серверийн байршуулалт, өгөгдлийн
нөөцлөлт, баримтын хандалтын эрхийг шийдэх хэрэгтэй. Одоогийн хувилбарт
хэрэглэгч бүр зөвхөн өөрийн баримттай ажилладаг тул хэлтсээрээ хуваалцан
ашиглах бол эрхийн нэмэлт зохицуулалт шаардагдана. Мөн хэрэглээний
хэмжээнээс хамаарч Gemini API-ийн квот хүрэлцэх эсэх, төлбөртэй түвшин
шаардлагатай эсэхийг үнэлэх нь зүйтэй.

\section*{Цаашдын хөгжүүлэлт}

Цаашид дараах ажлуудыг хийхээр төлөвлөсөн:

\begin{itemize}
\item \textbf{Асуултын орчуулга (query translation).} Асуултыг баримтын
хэл рүү орчуулж хайх аргыг турших. Үр дүнг одоогийн хайлттай харьцуулж,
тохирох threshold-ын утгыг туршилтаар сонгох;
\item \textbf{Production байршуулалт ба CI/CD.} Системийг үүлэн сервер дээр
HTTPS-тэйгээр байршуулж, шинэчлэлтийг автоматаар хүргэх CI/CD дамжлага
болон өдөр тутмын өгөгдлийн нөөцлөлт тохируулах;
\item \textbf{Мобайл түгээлт.} EAS build-ээр суулгах боломжтой APK/IPA
гаргаж, Expo Go-оос хараат бус болгох;
\item \textbf{Скан баримтын дэмжлэг (OCR).} Зураг хэлбэрээр хадгалагдсан
PDF-ээс текст ялгах давхарга нэмж, дэмжигдэх баримтын хүрээг тэлэх;
\item \textbf{PDF доторх хүснэгт, зургийн боловсруулалт.}
Одоогийн систем PDF-ээс текст ялгадаг бөгөөд хүснэгтийн мөр, баганын
харгалзааг тусгайлан хадгалдаггүй, зураг болон диаграмын агуулгыг
боловсруулдаггүй. Хүснэгтийг бүтэцтэй нь ялгах, зураг диаграмд multimodal
загвараар тайлбар үүсгэж индексжүүлэх аргыг турших;
\item \textbf{Хариултын streaming.} Хариулт үүсэх явцад бэлэн болсон
хэсгүүдийг клиентэд дамжуулж, хэрэглэгч уншиж эхлэх боломжтой болгох.
\end{itemize}

Энэ төслөөр би баримт боловсруулалт, вектор хайлт, хариулт үүсгэлтийг
нэг системд холбож, вэб болон мобайл клиентээс ашиглаж сурсан. Хөгжүүлэлтийн
явцад гарсан алдааг оношлох, засвараа турших, үр дүнгээ тэмдэглэх дадлага
хийв. Цаашдын ажилд одоогийн MVP-г тогтмол ашиглах орчинд бэлтгэж,
хайлтын чанарыг олон төрлийн баримт, асуултаар үнэлэх шаардлагатай.
