Дадлагын гол үр дүн нь ажиллаж буй систем төдийгүй түүнийг бүтээх явцад
эзэмшсэн мэдлэг, ур чадвар юм. Энэ бүлэгт тэдгээрийг онолын мэдлэгээ
практикт хэрэгжүүлсэн байдал, инженерийн дадал, ажлын арга барил гэсэн
гурван бүлэгт хувааж нэгтгэв.

\section{Онолын мэдлэгийг практикт хэрэгжүүлсэн байдал}

Их сургуулийн хөтөлбөрөөр үзсэн өгөгдлийн сан, алгоритм, магадлалын онолын
мэдлэг дээр RAG, embedding, вектор хайлт гэсэн шинэ сэдвүүдийг бие даан
судалж (3-р бүлэг), судалгаагаа шууд ажиллдаг код болгож хэрэгжүүлэв
(5-р бүлэг). Энэ явцад дараах чадварууд төлөвшсөн:

\begin{itemize}
\item Эрдэм шинжилгээний өгүүллийг (RAG, MMR, HNSW) уншиж, томьёог
хэрэгжүүлэлт болгох: MMR-ийн ерөнхий томьёог greedy алгоритм болгон бичиж,
$sim_2$-ийн үүрэгт Jaccard хэмжигдэхүүнийг сонгох зэрэг практик шийдвэрүүдийг
өөрөө гаргах;
\item онолын таамгийг бодит өгөгдлөөр шалгах: «олон хэлний embedding нэг
огторгуйд буулгадаг тул хэл дамнасан хайлт ажиллана» гэсэн таамаг зөвхөн
хэсэгчлэн биелдэгийг (кирилл--латин хос $\approx0.35$ төстэй байдал)
хэмжилтээр тогтоож, түүндээ тохирсон шийдэл гаргах;
\item хязгаарлагдмал нөөцөд (үнэгүй түвшний квот, тэг төсөв) багтаан
архитектурын сонголт хийж, сонголт бүрээ үндэслэлтэй баримтжуулах.
\end{itemize}

\section{Инженерийн дадал, хэрэглэсэн технологи}

Сервер талд Fastify + TypeScript (ESM) дээр домэйн модулиудад хуваасан API
бүтээж, PostgreSQL-тэй ORM-гүйгээр шууд SQL-ээр ажиллах, транзакц ашиглах,
migration системээр бүтцийн өөрчлөлтийг удирдах дадал эзэмшив. pgvector,
HNSW индекс зэрэг вектор хайлтын дэд бүтцийг бодит санд тохируулан
ашигласан. Гадаад API-тай ажиллахдаа rate limit, багцлалт, exponential
backoff, timeout, fallback гинж зэрэг найдвартай байдлын хэв маягуудыг
хэрэгжүүлсэн нь «алдаа гардаг орчинд ажилладаг код» бичих сургамж болов.

Клиент талд нэг React мэдлэг дээр тулгуурлан вэб (React + Vite + Tailwind)
болон мобайл (React Native + Expo) гэсэн хоёр платформын аппликейшн зэрэг
хөгжүүлж, хоёр клиентийн үйлдлийн ижил байдлыг (parity) хадгалах, мобайлын
онцлог бэрхшээлийг (API хаяг олох, эмулятор ба бодит утасны ялгаа, touch
gesture-ийн зөрчил) шийдэх туршлага хуримтлуулав. Нэвтрэлтийн системийг
Better Auth-аар хэрэгжүүлж, session удирдлага, нууц үгийн hash, олон
хэрэглэгчийн өгөгдлийн тусгаарлалтыг бүх давхаргад нэвт шүүх зарчмаар
хангах аюулгүй байдлын сэтгэлгээ төлөвшсөн. Мөн Docker Compose-оор бүрэн
стекийг тодорхойлох, image-ийн layer cache-д тохирсон Dockerfile бичих,
monorepo (pnpm + Turborepo) удирдах зэрэг DevOps суурь дадлыг эзэмшив.

\section{Асуудал шийдэх, баримтжуулах арга барил}

Техникийн мэдлэгээс гадна дадлагын хамгийн үнэ цэнтэй өв нь ажлын арга
барил байв:

\begin{itemize}
\item \textbf{Системтэй оношилгоо.} 6-р бүлэгт өгүүлсэн асуудлууд бүгд
хэд хэдэн алдаа давхарласан, нэг нь нөгөөгөө далдалсан тохиолдлууд байсан
тул таамгаар засахын оронд давхарга бүрийг тусгаарлаж, лог болон хэмжилтэд
тулгуурлан шалтгааныг нэг нэгээр нь батлах дадал тогтов.
\item \textbf{Баримтжуулалтын соёл.} Алдаа бүрийг дугаартай (ERR-NNN)
бүртгэж, шийдвэр бүрийг үндэслэлтэй нь хамт шийдвэрийн бүртгэлд (decision
log) хөтөлснөөр «яагаад ингэж хийсэн бэ?» гэсэн асуултын хариу хэзээд
олддог болсон. Threshold-ын түр шийдэл мэт буулт хийсэн газраа ил тэмдэглэх
нь ирээдүйн засварыг хялбарчилдаг гэдгийг ойлгов.
\item \textbf{Баталгаажуулалтад суурилсан хөгжүүлэлт.} Өөрчлөлт бүрийг
smoke тест, typecheck, build-ээр шалгаж, «ажиллаж байгаа» гэдгийг таамаг
биш ажиглалтаар нотлох; бүрэн шалгаж амжаагүй зүйлээ (500 мянган
тэмдэгтийн бүрэн гүйлт гэх мэт) тайланд ч, бүртгэлд ч шударгаар тэмдэглэх.
\item \textbf{Төлөвлөгөөт ажиллагаа.} Удирдагчаар батлуулсан төлөвлөгөөний
дагуу өдөр бүрийн зорилттой ажиллаж, гарсан хазайлтыг (даалгаврын дараалал,
технологийн өөрчлөлт) нуухын оронд үндэслэлтэйгээр баримтжуулж хэвшсэн.
\end{itemize}
